# π0.5 on LIBERO: reproduction and analysis

This repo reproduces Physical Intelligence's π0.5 (`pi05_libero` checkpoint) on the LIBERO-Long benchmark and analyses its successful and failed trajectories.

- **Our code** (`src/vlalab`): the inference pipeline, the flow-matching sampler, the policy server, the LIBERO evaluation loop, recording, replay and analysis.
- **openpi** ([Physical-Intelligence/openpi](https://github.com/Physical-Intelligence/openpi), pinned in [envs/openpi.txt](envs/openpi.txt)): used only as a library for the network definition, the checkpoint reader and the tokenizer. It is never modified.

All GPU work runs as Kaggle jobs (Tesla T4 16 GB ×2). Analysis runs locally on CPU.

## Layout

```
src/vlalab/
  config.py            experiment config shared by every process (ArmConfig: policy / eval / bench / replay)
  policy/              policy side, Python 3.11 + JAX (runs in openpi's venv)
    checkpoint.py        load weights, norm stats, tokenizer
    pipeline.py          LIBERO obs -> model inputs -> LIBERO actions, step by step
    sampler.py           flow-matching sampler: prefix KV cache + Euler integration of the velocity field
    rng.py               initial-noise policy ("stream" = openpi behaviour, "episode" = per-episode seeding)
    policy.py            Pi05Policy.infer(obs, rng)
    server.py            websocket server (the simulator needs Python 3.8, the policy Python 3.11)
    replay.py            re-run recorded policy inputs offline (equivalence check, sampling spread)
  sim/                 simulator side, Python 3.8 (robosuite 1.4.1, mujoco 3.2.3)
    libero_env.py        env construction, observation preprocessing
    evaluate.py          closed-loop rollouts with receding-horizon chunk execution
    bench.py             latency benchmark
    recording.py         run output format (episodes.csv, one .npz per episode, videos)
  analysis/            local, CPU
    build.py             all tables and figures -> results/
    features.py          per-episode trajectory features (grasp attempts, stalls, re-plan disagreement)
    stats.py             Wilson intervals, exact McNemar test for paired configs
    verify.py            summary of the equivalence replay
    pack_replay.py       build the dataset for a replay job
experiments/*.yaml     one file per experiment (a list of arms); the exact settings of every reported run
kaggle/                push.py (build + push a job), job.sh (what runs on the GPU), fetch.py (download outputs)
envs/                  pinned environments: openpi commit, LIBERO client requirements
results/               tables and figures (generated by analysis/build.py)
```

## Setup

Requirements:
- A Kaggle account with phone verification (for GPU access) and the API token in `~/.kaggle/kaggle.json`.
- `pip install kaggle pyyaml`.
- For the analysis: `pip install -e ".[analysis]"`.

Optionally, clone openpi locally to read the library code the policy builds on. Nothing in this repo needs it at runtime on your machine:

```bash
git clone https://github.com/Physical-Intelligence/openpi openpi
git -C openpi checkout 215abfb217dbac7d5f1273282331b9b1866c0479
```

On Kaggle, [kaggle/job.sh](kaggle/job.sh) builds two environments, following openpi's own instructions adapted to the Kaggle image:
- the policy environment: openpi's `uv sync`, Python 3.11, JAX;
- the simulator environment: Python 3.8, from [envs/](envs/).

It then puts `src/` on `PYTHONPATH` in both.

## Running experiments

An **arm** is one policy server plus one LIBERO client with its own config. A job runs one arm per GPU, so two configurations cost the quota of one.

```bash
python kaggle/push.py experiments/j2.yaml --push                                  # run an experiment
python kaggle/push.py experiments/j2.yaml --name j2_noise --set policy.noise=episode --push   # change a knob, all arms
python kaggle/push.py experiments/j1.yaml --set base_t2.eval.trials=1             # one arm; no --push = build only
kaggle kernels status <user>/vlalab-j2
python kaggle/fetch.py j2                                                          # -> runs/j2/<arm>/
python -m vlalab.analysis.build                                                    # -> results/
```

Every config field is documented in [src/vlalab/config.py](src/vlalab/config.py). The most used are:

| Field | Default | Meaning |
|---|---|---|
| `policy.num_steps` | 10 | Euler steps of the flow ODE |
| `policy.noise` | `stream` | how the initial noise is drawn (see [rng.py](src/vlalab/policy/rng.py)) |
| `eval.suite` / `eval.tasks` | `libero_10` / all | which tasks |
| `eval.trials`, `eval.start_trial` | 2, 0 | which LIBERO initial states (fixed, 50 per task) |
| `eval.replan_steps` | 5 | actions executed per call, out of the 10 predicted |

Code changes ship with the job: `push.py` packs the current `src/`, so editing the sampler or the evaluation loop needs no commit.

Kaggle notes:
- The CLI can't choose the GPU type; check `gpu.txt` in the output.
- `kaggle kernels output` only fetches the first ~500 files, so use `fetch.py`.

## Reported runs

All on `libero_10`. Initial states 0–1 are shared by every configuration, so configs are compared on identical starts.

| Experiment | Arms | What it tests |
|---|---|---|
| [smoke](experiments/smoke.yaml) | base | pipeline check on `libero_spatial`, 1 episode per task |
| [j1](experiments/j1.yaml) | base_t0, base_t2 | baseline (10 steps, replan 5) on initial states 0–3 |
| [j2](experiments/j2.yaml) | steps1, steps3 | number of flow integration steps |
| [j3](experiments/j3.yaml) | replan10, steps3_replan10 | executing the whole 10-action chunk open loop |
| [verify](experiments/verify.yaml) | ours/openpi × 3 configs | replay of recorded inputs: our pipeline vs openpi's `Policy` vs the recorded chunks |
| [j4](experiments/j4.yaml) | seed0, seed1 | moka pots (task 8), initial states 0–14, `noise=episode`: does a different noise draw rescue a failing state? |

Results: [results/README.md](results/README.md) indexes every table and figure, with the key numbers.

**Validation status.**
- The policy side (`policy/`) is checked against openpi's own `Policy` by the `verify` replay ([results/tables/verify.md](results/tables/verify.md)).
- The simulator side (`sim/evaluate.py`, `sim/bench.py`) mirrors openpi's LIBERO evaluation script line by line. It ran end to end on Kaggle in `j4` (30 episodes, none aborted, latency as in `j1`), and on the initial states shared with `j1` its outcomes are consistent with openpi's.

## Run output format

Each arm writes `runs/<experiment>/<arm>/` with these contents (details in [recording.py](src/vlalab/sim/recording.py)):
- `config.json`
- `episodes.csv` (one row per episode)
- `summary.json`
- `latency.csv`
- `episodes/<task>_ep<state>.npz`: per policy call, the call index, env step, robot state, the predicted 10×7 chunk and the two input images
- `videos/<task>_ep<state>_<success|failure>.mp4`
- `server.log`, `client.log`

Each job also writes `gpu.txt`, `versions.txt` (the openpi commit, and 0 local changes) and `vram.csv`.
